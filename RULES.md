# usd-museum rules

How the generated USD Museum is laid out, so it reads like real assets and stays valid USD.
Everything here is generated by usd-tour (`museum/src/export.py`). Change the generator, not
the files.

## 1. The repo holds only USD

- USD layers, textures and these two documents. No Python, no JSON sidecars.
- Anything a reader or viewer needs is in the USD itself:
  - **`doc`** on layers and prims: what it is, in a sentence.
  - **`assetInfo`** on each asset's root prim: `identifier` and `name`.
  - **`customData["museum"]`** for museum facts: an exhibit's id, title, "look for", working
    group, spec chapters and belt units. On each piece: what it shows, its reference, the U7
    features and rules it covers, its forgeries.
  - **`customLayerData`** on `tour.usda` for viewer plumbing: the load schedule (`tourLoad`)
    and whether the wing runs with OpenExec (`museum.exec`).
- Every layer's `doc` ends with the generator and the usd-tour commit it was built from.

## 2. Folders mirror prim paths

```
<wing>/
  <wing>.usda                     the wing (an assembly): its hall and galleries
  tour.usda                       the wing's tour: sublayers <wing>.usda, adds the camera,
                                  the frame range and the load schedule
  hall/rooms/                     the hall (an asset)
  <gallery>/                      a gallery: a group in <wing>.usda, a folder here
    <exhibit>/                    an exhibit (an asset)
```

The prim `/<wing>/<gallery>/<exhibit>` is the folder `<wing>/<gallery>/<exhibit>/`. If you can
see a prim in usdview, you can find its files.

The wing keeps the asset and the tour apart. `<wing>.usda` is the museum's content and opens
on its own. `tour.usda` adds what only a guided tour needs (camera, frame range, schedule).

## 3. Every asset has the same shape

```
<name>/
  <name>.usda          entry: what others reference
  payload.usda         the contents, behind the entry's payload
  parts/               further layers the contents compose (references, sublayers, variants)
  textures/            images
  forgeries/           exhibits only: one override layer per planted mistake
```

- **The entry `<name>.usda` is small.** It has `defaultPrim = "<name>"`, the root prim's
  `kind`, `assetInfo`, `customData["museum"]`, and `payload = @./payload.usda@`. Notes on
  pieces are `over`s with `doc` and `customData` only, never geometry. Assemblies
  *reference* entries; they never point past them into `payload.usda` or `parts/`.
- **The names don't vary:** `payload.usda`, `parts/`, `textures/`, `forgeries/`. Other files
  in the asset folder (an exhibit's `weak.usda` sublayer, the lists exhibit's `cells/`) are
  part of what that exhibit demonstrates. They are composed from `payload.usda`.
- **Paths are relative and stay inside the asset.** They start with `./`, or `../` only to
  climb back to the asset's own root. No asset reaches into a sibling. Copy any asset folder
  anywhere and it still opens. The only paths that cross folders are the wing's references
  to its assets and a forgery's sublayer of its exhibit.
- **Names:** prim name = folder name = entry file name. Lowercase, and valid as a prim name
  (letters, digits, `_`).

## 4. Kinds

| Prim | Kind |
|---|---|
| wing root | `assembly` |
| `hall`, each gallery | `group` |
| each exhibit root | `assembly` (it holds component models) |

Galleries and the hall are the load schedule's **carriers**. Each carrier's children hold
payloads (through their entries). Loading a carrier loads its exhibits and nothing else.

## 5. File formats

| Format | Use it for |
|---|---|
| `.usda` | Entries, wings, tours, forgeries, composition, any layer that exists to be read. The default. |
| `.usdc` | Heavy data: large meshes, crowds, animation caches. Rough line: over ~1 MB of text, or data nobody reads. |
| `.usdz` | Only where the exhibit is about packages (packages, file formats). Never as working source. A whole-museum `.usdz` can be built for handing out; it is a release artifact, not the repo. |

## 6. Forgeries

A **forgery** is a planted mistake: what a viewer with one specific bug would show. It is valid
USD with the wrong picture in it. Next to the correct exhibit, the difference must be obvious.

- **One override layer per forgery:** `<exhibit>/forgeries/<key>.usda`. It sublayers
  `../<exhibit>.usda` and overrides only what the bug changes. Its `doc` names the bug and
  what to look for. Open it in usdview to see the broken version; open the entry to see the
  correct one.
- **Write the bug as the bug where USD can say it:** a variant selection, `active = false`
  for something a broken reader drops, a value it misreads, a connection it loses.
- **When overrides can't express it, keep an edited copy.** For example, an exhibit's
  relocates can't be undone from a stronger layer. The copy goes in `forgeries/<key>/` and
  `forgeries/<key>.usda` sublayers it, so the entry path is the same for every forgery. The
  `doc` says why.
- **Every forgery is checked:** composed, it matches the forged copy that usd-tour's
  `planted.py` makes (same drawable prims, values, connections and targets).

## 7. Valid USD

- **Every entry passes `usdchecker`.** Exceptions are exhibits that break USD on purpose
  (for example `composition/errors/cycles`). Each one says so in
  `customData["museum"]["expected_errors"]`, and a wing or tour that contains one inherits
  only those errors.
- **Every exported exhibit composes the same as the one it was built from.** The tour matches
  the built wing in each exhibit's world bounds across its window, the camera and the hall.
  The exporter checks both and fails on any difference.
- **Nested payloads are normal:** wing → exhibit entry → `payload.usda`. Viewers must handle
  them the way OpenUSD does.
