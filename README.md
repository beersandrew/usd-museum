# usd-museum

The USD Museum as real assets: wings, galleries and exhibits laid out the way a production
asset library would be. Each exhibit also carries its forgeries as small override layers.
[RULES.md](RULES.md) describes the layout.

This repo holds assets only: no code. Everything here is generated by
[usd-tour](../usd-tour) (`museum/src/export.py`). Rebuild a wing instead of editing it:

```sh
cd ~/git/usd-tour
kit/py museum/src/export.py composition       # writes ~/git/usd-museum/composition/, then checks it
kit/py museum/src/export.py museum            # museum.usda, tour.usda (export the wings first)
```

## The whole museum

| File | What it is |
|---|---|
| [museum.usda](museum.usda) | The museum as one assembly: ten wings, each referenced from `./<wing>/<wing>.usda` and placed and timed where usd-tour's `compose.py` puts them, plus the corridors between them |
| [tour.usda](tour.usda) | The guided tour, 16,665 frames (11.6 minutes): sublayers `museum.usda` and adds the camera, the load schedule and the doors closed between wings |
| [tour_cam.usdc](tour_cam.usdc) | The tour camera's path, referenced by `tour.usda` (binary: about 16,000 samples) |

The whole tour runs with OpenExec off, so it leaves out the Rigging wing, which is its own
tour (`rigging/tour.usda`).

62 exhibits and 420 forgeries. 410 forgeries are override layers; 10 are edited copies
because overrides can't express them (relocates, MaterialX and a few others; each says why).

Rigging is the one wing that runs with OpenExec on (its `tour.usda` says `exec = 1` in
`customLayerData`). It holds OpenExec's two exhibits, split out of Animation on Nov 9, so
Animation runs with exec off. The whole-museum tour in usd-tour runs with exec off and leaves
Rigging out.

## Known problems

Each of these is in the usd-tour build, not the export. The exported files match the
originals exactly.

- `instancing/crowds/crowds`: references `textures/sign_crowd_wrongcard.png`, which doesn't exist.
- `instancing/points/points`: material bindings in the prototypes target `/Books/Looks/...`,
  outside the referenced prim, so they don't resolve.
- `materials/color/spaces`: the label mesh `/spaces/Dais/Label` sits under the dais mesh;
  gprims can't nest.

Two pieces depend on usdview's environment, not on the files:

- **Variant fallbacks** (`composition/arcs/variants`, the "fallback" piece): global variant
  fallbacks come from a plugin (`UsdVariantFallbacks` in a `plugInfo.json`: `wrap` falls back to
  `checks`), never from a layer. Without that plugin the piece shows its `nofallback` forgery.
- **Skinned figures** (`animation/characters/skinning`, `instancing/crowds/crowds`): OpenUSD 26.11
  on Metal drops GPU-skinned meshes over many frames. Set `USDSKELIMAGING_FORCE_CPU_COMPUTE=1`
  (usd-tools' `view.sh` does) to use the CPU path.

`usdchecker` fails on the three content problems, and on their wings and tours. It also fails, on purpose,
on the five exhibits whose `customData["museum"]["expected_errors"]` says why.

## Viewing

Open a file in OpenUSD's usdview and press Play. Tours play through their camera:

```sh
usdview tour.usda --camera /museum/tour/tour_cam                  # the whole museum
usdview composition/tour.usda --camera /composition/tour/tour_cam # one wing
usdview composition/arcs/arcs/arcs.usda                           # one exhibit
usdview composition/arcs/arcs/forgeries/noinherit.usda            # the same exhibit, one planted mistake
```

The Rigging wing needs OpenExec, which usdview reads from the environment:

```sh
USDIMAGINGGL_ENGINE_ENABLE_EXEC_SCENE_INDEX=1 usdview rigging/tour.usda --camera /rigging/tour/tour_cam
```

Stock usdview loads every payload; the whole museum is light enough (about 12,000 prims).
[usd-tools](https://github.com/beersandrew/usd-tools) `view/view.sh FILE` adds conveniences:
the tour camera, OpenExec and the workarounds below set from the file, and the load schedule in
`tour.usda` applied as the camera moves.
